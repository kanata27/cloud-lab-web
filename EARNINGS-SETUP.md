# Заработки — подключение

Страница: https://kanata27.com/stat-panel/earnings

Подготовлено по переданному ZIP. Фото и логика дат страницы посещений не изменены. В старой панели добавлена только навигация между разделами.

## Один раз перед публикацией

1. В Cloudflare открой **Storage & databases → D1 SQL Database → Create database**. Создай `kanata-earnings-preview`.
2. Скопируй **Database ID**. В репозитории открой `wrangler.preview.jsonc`, замени `00000000-0000-0000-0000-000000000000` в `database_id` на этот ID.
3. Создай вторую базу `kanata-earnings-production`. Её ID впиши в `wrangler.production.jsonc`. Используй разные базы, чтобы пробные записи не попадали в настоящую статистику. ID базы не является секретом.
4. В настройках токена Cloudflare, который уже хранится в GitHub как `CLOUDFLARE_API_TOKEN`, добавь разрешение **Account → D1 → Edit** для своего аккаунта. Если создаёшь новый токен, сохрани прежние разрешения Workers/DNS и замени значение GitHub Secret. `CLOUDFLARE_ACCOUNT_ID` прежний.
5. Перенеси файлы архива в ветку `feature/earningsPage` или другую `feature/*` и отправь коммит в GitHub. Проверки и публикация на preview запустятся автоматически, без Pull Request. Ручной запуск **Actions → Cloudflare site → Run workflow → эта ветка → preview** тоже доступен. Таблицы создаст миграция автоматически; SQL вручную выполнять не нужно.
6. На `https://preview.kanata27.com/stat-panel/` войди своим нынешним паролем. Открой «Заработки», добавь точку и пробную запись, обнови страницу, проверь редактирование через ⋯ и удаление. Для входа на preview его origin уже должен быть разрешён существующим AWS API, как при первоначальном переносе сайта.
7. После проверки слей ветку в `main`; запусти workflow из `main` с **production**. При включённом прежнем автодеплое публикация запустится при слиянии. Убедись, что production ID заполнен до слияния.

База сохраняется отдельно от Worker: обновление сайта не удаляет записи. Скрипт публикации останавливается, если реальный ID не указан. Сначала применяется миграция, затем публикуется Worker. GitHub Actions проверяет код и браузерные сценарии до публикации.

## Что работает

- День, начало/конец, окончание на следующий день; часы считаются по Europe/Prague.
- CZK, EUR, USD обязательны, нулевые суммы допустимы. Дополнительные валюты — из доступных курсов ECB, включая PLN и HUF.
- Свои точки создаются в форме выступления; в сохранённой строке точка показана обычным текстом.
- ⋯ → изменить все данные или удалить с подтверждением. Конфликт изменений из другой вкладки не перезаписывает более новую запись.
- Суммы, почасовой доход, дневной график суммы/часа, сравнение точек и фильтр периода/точки. Почасовой показатель за период = общий доход / общее время, а не среднее отдельных ставок.
- Сохранение на сервере D1, доступ с разных устройств после входа. Записи не хранятся только в браузере.

## Валюты и вход

Курсы загружаются сервером из Frankfurter v2, источник ECB. Берётся доступный курс на дату выступления (в выходной — предыдущий опубликованный). Исходные суммы и использованные курсы сохраняются вместе с записью. При изменении суммы/времени курс остаётся прежним, при смене даты пересчитывается. Итоги в евро суммируют исторические эквиваленты записей, а не переводятся по сегодняшнему курсу. Это справочная конвертация без комиссии обменника. Если сервис курсов недоступен и сохранённого курса нет, запись не сохраняется и форма показывает ошибку. Для новых записей за сегодня доступен последний опубликованный курс, он фиксируется при сохранении.

API проверяет нынешний Bearer-токен через защищённый AWS `/stats` перед каждым обращением к заработкам. Декодирования JWT без проверки нет. При недоступном AWS доступ закрывается до восстановления. Схема рассчитана на одного владельца: все пользователи с действующим доступом к прежней панели получают доступ к одному журналу заработков. AWS API и DynamoDB не изменяются.

Период отчёта ограничен 366 днями, максимум 2000 записей за запрос. Будущие/незаконченные выступления не сохраняются; спорные времена во время перевода часов требуют выбора однозначного времени. Пересечения выступлений не запрещены. График показывает дни с выступлениями.

## Разработка и резервная копия

Node.js 24: `npm ci`, затем `npm run dev`. Локальная D1 создаётся автоматически и не касается облачных данных. Вход/серверная авторизация используют существующий AWS API; браузерные тесты подменяют запросы и не пишут реальные данные.

Проверки: `npm test`; `npx playwright install chromium`; `npm run test:browser`.

Резервная копия перед будущими изменениями схемы:

```sh
npx wrangler d1 export EARNINGS_DB --remote --config wrangler.production.jsonc --output earnings-backup.sql
```

Храни выгрузку приватно, не коммить в репозиторий. Для отката интерфейса можно вернуть прежний коммит Worker, сохранив D1. Миграция добавляет только три новые таблицы в отдельную базу; старые данные статистики не затрагивает.

Документация: https://developers.cloudflare.com/d1/ · https://developers.cloudflare.com/workers/static-assets/binding/ · https://frankfurter.dev/
