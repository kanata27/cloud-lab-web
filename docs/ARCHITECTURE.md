# Архитектура и безопасность

## Компоненты

| Компонент | Назначение |
|---|---|
| Workers Static Assets | Публичный сайт, фото, файлы |
| Cloudflare Access | Вход по email OTP, сессия до 8 часов, Allow одного email |
| Worker index.js | Проверка подписи Access JWT, owner allowlist, маршрутизация |
| D1 каждой среды | Заработки, курсы, агрегаты посещений и журнал дедупликации |
| Frankfurter / ECB | Доступные опубликованные курсы на дату выступления |
| GitHub Actions | Проверки, preview feature-веток, управляемая публикация main |

Публичны `/`, точный список публичных ассетов и `POST /events`. Закрыты все страницы/ресурсы `/stat-panel/`, `/api/*`, `/earnings-api/*`. Ссылки `/statpanel` и `/statistics-panel` только перенаправляют на защищённый канонический путь. `www` — публичный псевдоним основного сайта; панель с него перенаправляется на apex.

`run_worker_first` охватывает всё, кроме точных публичных файлов. Поэтому забытый новый файл панели не начинает случайно отдаваться до авторизации. workers.dev и временные preview URLs выключены, неизвестный Host отклоняется. Сама главная страница и фотография обслуживаются Static Assets без Worker; аналитика не задерживает переход на YouTube/Instagram.

## Вход и API

Access стоит перед тремя закрытыми путями. Worker дополнительно криптографически проверяет `Cf-Access-Jwt-Assertion` через jose: RS256, ключи только настроенного team-домена, issuer, AUD конкретного приложения, exp/iat/nbf, тип app и точный разрешённый email. JWKS кэшируется с обновлением, перенаправление на другой адрес не допускается. Отсутствие настроек или ошибка сервиса закрывает доступ. Поддельные email-заголовки, старый AWS Bearer и фальшивые cookie не дают доступ.

Access хранит браузерную сессию в HttpOnly cookie. Приложение не получает пароль или OTP и не кладёт токен в sessionStorage/localStorage. Старый AWS sessionStorage-токен удаляется. Запросы только same-origin, CORS с AWS больше не требуется. Изменения данных требуют точного Origin; cross-site запросы отклоняются. SQL-параметры связаны через bind, тело ограничено по фактически прочитанным байтам. Приватные страницы и API не кэшируются, CSP допускает только свои скрипты. Выход направляет в Access logout, возврат страницы из BFCache перезагружает авторизацию.

Это защита от неавторизованного чтения/изменения, а не обещание невозможности взлома. Доступ к почте, аккаунту Cloudflare и ключам публикации остаётся границей доверия. Защити эти аккаунты MFA; GitHub-токен ограничь своим аккаунтом/зоной. JWT сам по себе действителен до exp: не считай локальную очистку страницы отзывом всех когда-либо скопированных токенов. При инциденте отзывай сессии через Access.

## Посещения и совместимость

`POST /events` принимает session_id, event_id UUID, event page_view/social_click, source qr/direct и допустимую platform. Время задаёт сервер. Отдельный Rate Limit binding каждой среды — 120 запросов в минуту на IP, до записи D1. Это ограничение Cloudflare на уровне расположения/узла, не строгий глобальный счётчик. Origin — дополнительная браузерная проверка, не удостоверение личности бота.

Вставка события и обновление сессии выполняются атомарно SQLite-триггером. event_id предотвращает повторный учёт одного события; порядок click-before-view поддержан. Для старых версий клиента без event_id сервер генерирует ID, поэтому их повторные отправки не дедуплицируются. Журнал event_id хранится 30 дней; по Cron за проход удаляется до 5000 старых строк. Исторические счётчики сессий и заработки не удаляются.

AWS-история хранится в base_* отдельно от новых счётчиков. Повторная выгрузка обновляет base до максимального экспортированного значения, не прибавляет её повторно и не меняет live. Счётчики AWS монотонные; ручное уменьшение старых данных импорт не переносит. Исходный экспорт не публикуется.

`GET /api/stats` сохраняет version:1, range, totals, daily, sources, destinations и UTC. До 90 дней за запрос; инсайты разбивают большие периоды. Весь счётчик сессии относится к дате started_at, как в старой Lambda. Пустые дни возвращаются нулями. Сессии без первого просмотра пока не входят в отчёт. Старые неизвестные источники импортируются как direct.

## Данные и доступность

Используются существующие D1 ID, миграция 0002 только добавляет analytics-таблицы. Earnings API и snapshots валют сохранены, авторизация вынесена в общий Worker. Preview отдельный: тестовые посещения и заработки не пишутся в production. Резервные копии D1 делаются до переключения и перед изменениями схемы; восстановление данных отдельно от отката Worker.

Сбой Access может закрыть панель, сбой D1 — остановить статистику/заработки. Публичные ссылки продолжают работать, если доступна раздача Static Assets. Ненадёжная доставка аналитики при закрытии вкладки/отказе сети остаётся прежним ограничением: долговечной очереди на устройстве нет. Cloudflare остаётся одним поставщиком; независимый резервный провайдер не добавлялся.

## Бесплатный тариф

Ориентир на дату подготовки: Workers Free — 100 000 динамических запросов в сутки, 10 мс CPU на вызов; D1 Free — 5 млн прочитанных и 100 000 записанных строк в сутки, 500 МБ на одну базу и 5 ГБ суммарно; Static Assets без выполнения Worker не расходуют динамическую квоту. Для входа одного владельца используется Access Free.

При твоей небольшой нагрузке эта схема рассчитана на бесплатные квоты, но это не безусловная гарантия. Одно событие обновляет несколько строк/индексов, поэтому 100 000 записей D1 не равны 100 000 посетителей. Запросы закрытых ассетов проходят Worker и тоже учитываются. Квоты общие с другими проектами аккаунта; при исчерпании Free динамическая часть может перестать отвечать до сброса. Следи за Workers Metrics и D1 Metrics, особенно CPU подписи JWT и rows written. Платный Workers автоматически включать проект не просит.
