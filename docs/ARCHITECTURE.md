# Архитектура после переноса

Браузер получает HTML, CSS, JS, фото и панель из Cloudflare Workers Static Assets. Для записи события, входа и чтения отчёта он обращается напрямую в существующий AWS API Gateway. Тот вызывает текущие Lambda; данные остаются в текущих DynamoDB. Регион бэкенда — eu-north-1.

## Что установлено по актуальному коду

| Область | Реализация |
|---|---|
| Фронтенд | Обычный HTML/CSS/JS, без React/Vite и серверного рендера |
| Публикация | Сборка по списку разрешённых файлов в `dist/`; Wrangler; GitHub Actions |
| Публичный сайт | `/` |
| Панель | `/stat-panel/`; исходники в `statistics-panel/` |
| События | `POST /events`: `session_id`, `event`, `source`, для social_click ещё `platform` |
| Источник | Наличие параметра `q` означает `qr`, иначе `direct` |
| Вход | `POST /login`: `{username,password}`; ответ `{token}` |
| Сессия | `sessionStorage.kanata_admin_token`, далее заголовок Bearer |
| Отчёт | `GET /stats?from=YYYY-MM-DD&to=YYYY-MM-DD&source=all|qr|direct` |
| Формат отчёта | `version:1`, `range`, `totals`, `daily`, `sources`, `destinations` |
| Ограничение интерфейса | До 90 дней, время UTC |

Этот перенос не добавляет новую Lambda или таблицу. Исходников действующих Lambda, схем PK/SK/GSI и IAM policy в репозитории нет; их нельзя восстановить достоверно по HTML. Рабочую логику сохраняем. Переносить её в заново выдуманный SAM-шаблон без исходников было бы дополнительным риском для статистики и входа.

База уже DynamoDB; миграции из PostgreSQL и SQL JOIN нет. Точные ключи надо читать через DescribeTable/Console. Sort Key в DynamoDB необязателен. Защита от Scan по всей истории и фактическое ограничение периода должны проверяться в бэкенде отдельно.

## Безопасность

При проверке 13.09.2026 действующий `/stats` без токена вернул `401 session_expired`. Это подтверждает только проверенный запрос, не полный аудит авторизации. При деплое smoke-проверка дополнительно требует отказа и для заведомо неверного токена.

Токен из текущего приложения сохранён в sessionStorage. Он доступен JavaScript этой вкладки; это не HttpOnly cookie. Строгая CSP без inline-скриптов и eval сокращает поверхность XSS, но не превращает frontend в границу авторизации. Сам HTML панели доступен публично; защищать нужно данные и операции API. «Выйти» очищает локальный токен; отзыв уже скопированного токена до срока истечения требует поддержки бэкенда.

AWS должен проверять подпись/срок действия токена и доступ к статистике на каждом запросе. Если токен JWT, недостаточно `decode`: нужны verify, разрешённый алгоритм и ожидаемые claims. `jsonwebtoken` — внешняя npm-зависимость, не встроенный модуль Node.js. Пароль проверяется по стойкому хешу на сервере. Эти свойства нельзя подтвердить без исходников Lambda.

В публикацию входят только публичные файлы. Исходники инфраструктуры, workflows, .env и выгрузки AWS не попадают в `dist`. Все JS вынесены в отдельные файлы. Для панели задан `Cache-Control: no-store`; fetch отчёта также использует `cache: no-store`. На самом API для `/login` и `/stats` тоже нужен `Cache-Control: no-store`.

CORS разрешает точные origins. Он управляет доступом браузера к ответу и не защищает `/events` от сторонних программ. Реальная защита сбора событий: проверка размера/схемы, допустимые имена событий/платформ, server-side ограничения нагрузки. Защита логина: ограничения попыток и отсутствие паролей/токенов в логах.

Нынешняя авторизация не использует cookies. Если позже перейти на HttpOnly cookies, `https://kanata27.com` и `https://api.kanata27.com` будут cross-origin, но same-site. `SameSite=None` только из-за поддомена не требуется. Потребуются `credentials: include`, точные CORS origins, `AllowCredentials`, защита от CSRF и корректные cookie attributes. Это отдельная миграция входа.

## Отказоустойчивость и цена

Для страниц нет отдельной VM, диска ОС, единственного домашнего сервера или ручного rolling restart. Cloudflare раздаёт статику своей сетью. Сбой AWS может временно остановить статистику/вход, но ссылки на YouTube/Instagram на уже работающем сайте не зависят от успешной отправки аналитики. Принципиально недоставленные события не гарантированно восстановятся: надёжная очередь доставки — отдельная функция.

AWS HTTP API/Lambda/DynamoDB — региональный бэкенд. Этот проект не добавляет резервный AWS-регион и не обещает абсолютную доступность. Резервное копирование DynamoDB защищает от потери данных, а не от всех региональных отказов.

Запросы к Static Assets бесплатны; здесь нет пользовательского Worker-обработчика на каждый запрос. [Тарификация Cloudflare](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/). При небольшой нагрузке разумный ориентир для оставшегося AWS — **$0–3 в месяц**, отдельно домен и налоги; это оценка после удаления прежних платных ресурсов, не лимит счёта. Фактическая сумма зависит от запросов, чтений DynamoDB, логов, хранения, резервных копий и общих льгот аккаунта. [API Gateway](https://aws.amazon.com/api-gateway/pricing/), [Lambda](https://aws.amazon.com/lambda/pricing/), [DynamoDB](https://aws.amazon.com/dynamodb/pricing/).

Жёсткий максимум интеграции именно HTTP API — **30 секунд**, не 29. Статистику за 90 дней надо получать существенно быстрее с Query/агрегатами и ограничением объёма. Повышать тайм-аут вместо исправления дорогого чтения не стоит. [Лимиты HTTP API](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-quotas.html).

## Адрес api.kanata27.com

Для экономии и работы нового фронтенда отдельный API-поддомен не обязателен: текущий HTTPS invoke URL уже работает. Все три вызова берут базовый адрес из `site.config.json`.

Если хочется красивый API-адрес, сначала подключи его к существующему API: ACM certificate в eu-north-1 → API Gateway Regional custom domain → API mapping на существующий stage → CNAME `api` на Regional domain name в Cloudflare, **DNS only**. Проверь login/events/stats, затем замени только `apiBase` в `site.config.json` и сначала проверь preview. Старый invoke URL до проверки не отключай. Это не повод заново создавать Lambda или DynamoDB. [Инструкция AWS](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-custom-domain-names.html).

## Воспроизводимость

Для новой части инфраструктуры используются `wrangler.preview.jsonc`, `wrangler.production.jsonc` и GitHub Actions. Текущие AWS-ресурсы остаются под прежним управлением. Позже их можно инвентаризировать и импортировать в Terraform/CloudFormation подходящим способом; шаблон, создающий ресурсы с похожими именами, не означает импорт.

`npm ci && npm run build && npm test` проверяет сборку и контракт событий. `npm run test:browser` запускает настоящий локальный Wrangler и Chromium, подменяя AWS-ответы тестовыми; внешние шрифты отключаются только в тестах. Тестовые отчёты находятся исключительно в tests и не публикуются. CI фиксирует версии npm-зависимостей и GitHub Actions; production доступен только с main, preview можно вручную развернуть из feature-ветки. `tools/dns-preflight.mjs` проверяет принадлежность DNS перед переключением, `tools/smoke.mjs` проверяет опубликованные маршруты и закрытый доступ без записи событий.
