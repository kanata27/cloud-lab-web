# Отключение оставшегося AWS

Начинать после успешной проверки production и финального импорта по MIGRATION-START.md. Команд удаления в workflow нет. Сохрани экспорт DynamoDB, код/конфигурации обеих Lambda, IAM роли, API routes/stages/CORS, логи, прежнюю настройку concurrency и данные Billing.

1. Старый writer `kanata-analytics-api` после финального Scan уже остановлен reserved concurrency=0. Не путай с `kanata-analytics-read`. Сохрани таблицу `kanata-analytics` и обе функции на короткий период отката; они больше не нужны новому сайту.
2. Проверь основную страницу и QR, все разделы панели, OTP с разрешённой почтой, отказ для другой почты/гостя, историю и новые события. В браузерной Network нового сайта не должно быть запросов на execute-api.amazonaws.com.
3. Посмотри обращения к старому API за переходный период. Старые открытые страницы могли ещё писать туда до остановки. Финальная выгрузка сделана только после остановки writer; импорт повторён в production.
4. После выбранного периода восстановления удаляй только подтверждённо относящиеся к проекту API Gateway, обе Lambda, их выделенные лог-группы и неиспользуемые IAM роли. Перед удалением роли проверь, не использует ли её другая функция. Секреты прежнего входа и сессии больше нигде не используются; сохрани приватную конфигурацию для оговорённого периода отката и затем удали.
5. DynamoDB удаляй последней, после проверки приватного JSON и SQL импорта. Её удаление не связано с новой D1 и необратимо без копии. Backup/export в AWS тоже могут продолжать стоить денег.
6. Если от прежней VM-архитектуры ещё остались ASG, EC2, ALB, NAT Gateway, EBS, public IPv4, snapshots, ECR или S3 артефакты — инвентаризируй их отдельно. Остановка EC2 не удаляет все связанные расходы, а ASG может создать её вновь. Не удаляй общие VPC/роли/бакеты по одному совпадению имени.
7. При наличии api.kanata27.com, ACM и его CNAME удаляй только подтверждённо ненужные записи. Не трогай основной домен Workers, почту, nameservers и чужие сервисы.
8. Проверь Billing/Cost Explorer через несколько дней: исторические расходы не исчезнут, новые начисления должны прекратиться по удалённым услугам. AWS-аккаунт закрывать для этого не требуется.

Итоговый работающий проект в AWS не обращается: публичный сайт + Worker + Access + D1 размещены в Cloudflare; курсы валют получает сервер из Frankfurter/ECB. Подписка/домен и любые оставшиеся ресурсы вне проекта оплачиваются по своим условиям.
