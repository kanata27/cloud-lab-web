# Отключение старых расходов AWS

Делай после успешной проверки основного домена и панели. Ничего из этого автоматически не выполняется при публикации сайта.

## Сначала установить зависимости

AWS → API Gateway → `dupt8l46y1` → **Integrations**. Для `/events`, `/login`, `/stats` проверь, что используются действующие Lambda, запиши их имена. Если там HTTP proxy/VPC Link/ALB вместо Lambda, сначала надо перенести эту конкретную зависимость; её нельзя удалять только потому, что фронтенд уже в Cloudflare.

В Lambda → **Configuration → VPC** проверь сетевые зависимости. Отдельный NAT Gateway для обычных вызовов DynamoDB вне VPC не нужен, но уже существующий NAT/VPC endpoint нельзя удалять, если через него ходят действующие функции или другие проекты.

## Отключить старую раздачу страниц

1. Убедись, что workflow для ECR/ASG заменён и нет второго действующего деплоя туда.
2. AWS → EC2 → **Auto Scaling Groups → cloud-lab-asg → Edit**. Установи **Min=0, Desired=0, Max=0**. Проверь, что нет scheduled actions, возвращающих прежний размер.
3. Дождись завершения старых EC2 и повторно проверь основной сайт, вход и реальное событие QR. Если всё работает, AWS-сервер для фронтенда больше не нужен.
4. EC2 → **Load Balancers** → выбери только прежний `cloud-lab-alb` → **Actions → Delete**. Если включена защита удаления, выключи её в Attributes. Этот шаг удаляет возможность быстрого возврата DNS на старый ALB.
5. Удали опустевшую `cloud-lab-asg` и её старую target group. Launch Template и IAM role старого EC2 можно убрать после проверки, что они не используются в других задачах.
6. EC2 → **Volumes**: удали только оставшиеся **Available** диски бывшего сайта. В **Elastic IPs** освободи неиспользуемые адреса этого проекта. Проверь ненужные snapshots/собственные AMI: они могут продолжать тарифицироваться.
7. В ECR сохрани несколько нужных образов для истории, затем настрой lifecycle/удали ненужные. После отказа от Docker-деплоя репозиторий ECR можно удалить целиком, если он больше нигде не нужен.

Оставь API Gateway `dupt8l46y1`, используемые им Lambda, таблицы DynamoDB, действующие секреты/настройки авторизации, IAM roles функций и нужные ACM certificates. Не удаляй «все старые API». Удаление EC2 не удаляет автоматически ALB, IPv4, NAT, snapshots и все EBS-диски.

## Ограничить оставшиеся расходы

| Где | Что проверить |
|---|---|
| DynamoDB → таблица → Additional settings | Режим **On-demand** при нерегулярной малой нагрузке; существующие ключи/индексы сохранить |
| DynamoDB → Backups | Резервная копия перед изменением инфраструктуры; PITR — по ценности данных, хранение оплачивается |
| DynamoDB → Deletion protection | Включить для рабочей таблицы |
| CloudWatch → Log groups | Retention, например 14 дней; исключить пароли, JWT и полные события с персональными данными |
| API Gateway → Stages → Route settings | Стартовые ориентиры: events 10 req/s burst 30; login 1 req/s burst 5; stats 2 req/s burst 5. Подстроить по фактическим метрикам |
| Lambda → Configuration → Concurrency | Не включать платную Provisioned concurrency без измеренной необходимости; reserved concurrency ограничивает параллелизм, но не является месячным лимитом расходов |
| Billing → Budgets → Create budget | Месячный cost budget, например $5; уведомления по фактической сумме 50/80/100% и прогнозу |
| Billing → Cost Explorer | После задержки биллинга проверить EC2, ELB, VPC, EBS, DynamoDB, Lambda, CloudWatch по отдельности |

Ограничение API Gateway работает best effort и не гарантирует жёсткий потолок расходов. Лимит логина по IP/пользователю должен быть в текущей серверной логике; маленький глобальный RPS не заменяет защиту от перебора. Частые Scan за 90 дней могут стоить больше всех посещений сайта, поэтому статистика должна читать ограниченный диапазон по ключу или агрегатам. [Throttling HTTP API](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-throttling.html).

Точный счёт по аккаунту нельзя рассчитать по одному скриншоту. Ориентир $0–3/месяц относится к небольшому serverless-сайту после удаления старого хостинга, без домена, налогов и других ресурсов аккаунта.
