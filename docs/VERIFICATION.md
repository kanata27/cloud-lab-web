## Сверка переноса данных

На настоящем экспорте сформированы 102 отчёта: общий период, точный исторический период, пустые периоды, каждый отдельный день и все три фильтра источника. Каждый ответ нового readStats сравнен с исходной Python handle_stats из переданной Lambda. Совпадают все поля кроме текущего generated_at. SQL импорт применялся дважды; результат не изменился.

История: 76 сессий, 89 просмотров, 27 переходов (18 YouTube + 9 Instagram), 20 сессий с переходом, 16.09–15.10.2026. Отдельными тестами проверены обновление финального baseline без потери live-событий, старый повторный импорт, click-before-view, неизвестный source, незавершённая AWS строка без первого просмотра, полнота выгрузки и ошибочные диапазоны.

## Проверка защиты

Неверная подпись/issuer/audience/срок, будущий nbf, слишком старая сессия, чужой email, неподходящий тип токена, старый Bearer и поддельный email-заголовок не дают доступ. Ошибка JWKS закрывает вход. Частные страницы и API не доходят до чтения данных без авторизации. Удаление cookies и выход закрывают страницы и оба API; приватный ответ не становится cacheable. Проверены неизвестный Host, вложенное кодирование пути, чужой Origin, фактический размер тела, неверные события, дедупликация, 429 и очистка журнала без удаления истории.

Новый интеграционный браузерный сценарий использует настоящий Worker и локальную SQLite: отправляет публичный просмотр дважды с одним event_id и клик, получает один просмотр/один клик через API и интерфейс Visits, выходит и проверяет отказ для Visits/earnings/session API. Внешние аккаунты и рабочие базы не используются.

## Границы проверки

Браузерные тесты используют loopback-сервер с изолированным Access stand-in: ephemeral RSA ключ, тестовая HttpOnly cookie и подписанный assertion только внутри tests/support. Эти файлы не включены в dist/Worker entry. Другие тесты клиента подменяют ответы API и курсов, чтобы не зависеть от сети. Реальная доставка email-кода, настройки твоих Allow-политик, содержимое production D1 и сетевые задержки проверяются на защищённом preview после настройки аккаунта.

Chromium запущен через внешний PLAYWRIGHT_CHROMIUM_EXECUTABLE доступного тестового окружения; это не зависимость приложения. В GitHub Actions устанавливается обычный Chromium Playwright. Успешный dry-run не доказывает права твоего API token или корректность реального Access AUD. Секрет email нужно добавить в обе среды, placeholders заменить. AWS не отключался, финальная выгрузка ещё понадобится.
