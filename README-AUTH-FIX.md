# Исправление входа на страницу заработков

После публикации страница показывала «Сервис входа временно недоступен».
Причина была в worker/earnings.js: режим redirect: 'error' отвергается runtime
Cloudflare из проекта ещё до отправки запроса в действующий AWS API.

Исправление использует redirect: 'manual'. Перенаправления не выполняются,
а ответы 3xx отклоняются существующей проверкой response.ok. Действующая
проверка сессии через AWS сохранена.

## Как установить

1. Распакуй архив в корень проекта в той же ветке feature/…, где работаешь
   над заработками. Разреши замену worker/earnings.js. Папка tests из архива
   должна объединиться с существующей tests.
2. Сделай commit и push этой ветки в GitHub. Push в feature/… запускает
   проверки и публикацию preview автоматически.
3. В Actions → Cloudflare site дождись зелёных check и deploy именно у
   запуска с событием push. Запуск pull_request выполняет только проверки.
   Для ручного запуска: Run workflow → твоя ветка → target: preview.
4. Открой https://preview.kanata27.com/stat-panel/earnings и обнови страницу.
   Если сессия уже истекла, войди заново обычным паролем панели.
5. Добавь точку и запись о заработке, обнови страницу и проверь, что запись
   сохранилась.

Токен Cloudflare, GitHub Secrets, ID баз D1 и настройки доменов менять
не требуется. Эти файлы в архив не включены. Публикация на production
выполняется отдельно, после проверки preview.

## Проверка исправления

Локально прошли npm run build и все 14 тестов npm test.
Новый тест запускает код в настоящем workerd из установленного Wrangler:
проверяет рабочую, истёкшую и отсутствующую сессию, отказ в доступе,
перенаправление, ошибку сервиса и некорректный ответ.
Перед исправлением этот тест воспроизводил ошибку входа; после исправления
все семь сценариев проходят. AWS в этом тесте заменён изолированным
тестовым сервисом, реальные данные и пароли не используются.

Дополнительные зависимости устанавливать не нужно: workerd и esbuild
уже входят в зависимости версии Wrangler из package-lock.json.
